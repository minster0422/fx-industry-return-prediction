# 자료 버전 지도

2025년 폴더에는 파일명에 `최종`, `찐`, `베타`, `수정`이 섞여 있어 이름만으로 최종본을 판단할 수 없다. 이 저장소는 다음 우선순위를 사용한다.

| 자료 | 기준 역할 | 그대로 믿지 않는 부분 |
|---|---|---|
| DBpia 논문 | 외부에 공식 출판된 제목·저자·요약·핵심 주장 | 3쪽 분량이라 세부 계산 정의가 부족함 |
| 학회 최종 PPT | 발표 현장에서 제시된 표·수치·그림 | 애니메이션 이전 화면과 계산 근거가 보이지 않음 |
| 발표 대본 | 발표자가 의도한 논리·강조점·화면 전환 | 일부 변수가 누락되고 미완성 문구가 남아 있음 |
| 합본 R 코드 | 실제로 시도한 계산 절차 | 중간 수정이 누적되어 설명과 코드가 다름 |
| 원본·파생 CSV | 당시 실행 입력과 수동 정제 결과 | 생성 경로와 버전이 완전히 기록되지 않음 |
| 이 저장소의 Python 포트 | 변수와 시점을 명시한 구조적 재현 | R과 라이브러리가 달라 숫자 동일성을 보장하지 않음 |

## 충돌 처리 원칙

1. 과거 자료를 조용히 덮어쓰지 않는다.
2. `보고된 값`, `코드로 계산되는 값`, `V2 정의`를 별도 열과 파일로 둔다.
3. 파일 수정시간보다 계산 계보와 공개 여부를 우선한다.
4. 재현되지 않는 주장은 실패로 숨기지 않고 결과로 기록한다.
5. 개인정보·영수증·통장 사본·수업자료는 공개 저장소에 넣지 않는다.

## 현재 채택한 기준

- 연구 서사: 학회 대본과 최종 PPT
- 공개된 주장: DBpia 논문과 최종 PPT 표
- 2025 계산 구조: `환율 민감도.R` 합본 코드
- 산업 이진행렬과 보고 규칙: 팀 폴더의 소형 CSV
- 원시 시장 패널: 두 팀 폴더에 중복 보관된 24,300행 CSV
